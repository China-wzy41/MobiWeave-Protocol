## 待 A 决定

执行下面的正式轮次之前，先看硬件清单里的三项决定。本文不代选。

1. **只有 RSSI、没有 SNR 时，#3 如何验收。** 记录上 SNR 填 `null`。这样是否算通过 #3 的 RSSI/SNR 一项，待 A 决定。见 [第 5 节](#rssi-record)。
2. **测试前是否改成合规射频配置。** 出厂 22 dBm、LEVEL2 带宽 500 kHz，超过工信部 2019 年第 52 号公告附件所写的 10 mW（e.r.p.）和 400 kHz。建议是功率 ≤10 dBm、LEVEL3（250 kHz，SF8）。这一档 32 字节空口约 62 ms，短于 LEVEL2（SF11）的约 206 ms，发送间隔不因此加长。LEVEL3 的发送间隔和 16 字节回执时间待 AUX 实测确认，这里不写秒数。代价是接收灵敏度下降、距离变短；再加上功率 ≤10 dBm，覆盖范围明显缩小，适合近距离测试。见 [第 3 节](#interval)。
3. **M0/M1 在出厂设置下是模块输出脚。** ESP32 不能配成输出去驱动。接线按硬件清单：不接，或只配成输入。是否改方式二，待 A 决定。

## 1. 前提与拓扑

前提：[#5](https://github.com/China-wzy41/MobiWeave-Protocol/issues/5)、[#6](https://github.com/China-wzy41/MobiWeave-Protocol/issues/6)、[#8](https://github.com/China-wzy41/MobiWeave-Protocol/issues/8) 完成；两套节点（ESP32-S3 + DX-LR22 + 天线）按[接线表](../Firmware/hardware/硬件清单与接线.md)接好；测试固件由 A/B 另行提供。**不接天线不发射。**

- 节点 TX（发送端）、节点 RX（接收端）。各连一台电脑，或连同一台电脑的两个 COM 口，记录串口日志。
- 固定近距布局：两天线的间距、高度、朝向、遮挡在开始前固定并拍照，全程不移动。近距时两根天线不要贴在一起；“至少隔开约 1 米”是经验做法，**待实测**。
- 建议用“发送—回执”：TX 发带序号的数据包，RX 记录后回发同序号回执，TX 用自己的时钟记往返时间（RTT）。实验方法要求不要把两台设备的时间戳直接相减当成单向延迟。**是否加回执由 B 的协议决定，待确认。**

## 3. 按空口时间安排发送间隔

<a id="interval"></a>

1. 空口时间用 Semtech LoRa 公式估算。公式说明见 [SX1261/2 产品页的 LoRa Time-on-Air](https://www.semtech.com/products/wireless-rf/lora-connect/sx1262)。**本模块芯片是 LLCC68，不是 SX1262**，SF/BW 能否组合以 [LLCC68 数据手册](https://www.hy-line-group.com/products/hcp/datasheet/semtech/llcc68-datasheet.pdf) 为准。符号 \(T_{sym}\)、前导码、载荷符号数和 \(T_{air}\) 的式子写在[硬件清单 2.8](../Firmware/hardware/硬件清单与接线.md)。式中 CRC=1、IH=1 只表示“开启 CRC”“隐式包头”这两个开关取 1；**206 ms / 144 ms 那一栏是按显式包头、射频 CRC 关闭估算的**，不要用隐式包头或 CRC 开启去套这些毫秒数。
2. 手册已经给出各 LEVEL 的 SF/BW/CR（见硬件清单）。LEVEL0/1 与 LLCC68 冲突，**待实测确认**，在 `AT+HELP` 读回之前不要使用这两档。只有读回结果和手册表对不上、又没有 SF/BW 时，才用空速做粗估：\(T_{air} \approx 8 \times PL / \text{空速}\)，并在记录里标明“估算”。
3. AUX 是模块状态输出：高 = 发送中、接收中或模式切换中；低 = 完成；检测到接收数据时会提前 2–3 ms 拉高（技术手册 2.2，应用指导 3.2、3.3.5）。**每次发送前等 AUX 变低。** 有条件时用 ESP32（或示波器、逻辑分析仪）量 AUX 高电平持续时间，作为空口时间的实测值。
4. 一个收发周期的下限：
   \(T_{cycle} = T_{uart,tx} + T_{air,data} + T_{proc} + T_{air,ack} + T_{uart,rx}\)
   UART 时间约为 \(10 \times 字节数 / 波特率\)（8N1）。9600 bps 时每字节约 1.04 ms。\(T_{proc}\) 是模块和 MCU 的处理时间，**待实测**。
5. 发送间隔取 \(T \ge k \times T_{cycle}\)。先做小规模试跑，确认模块里没有队列积压，再冻结 k。目的是避免把“灌包太快、缓冲溢出”算成无线丢包。
6. 预估单轮时长 = 包数 × T，事先确认场地够用。
7. **当前起点（只针对出厂 LEVEL2 的理论估算）：** 32 字节数据约 206 ms，16 字节回执约 144 ms，示例里的串口合计约 50 ms，单个周期约 0.4 s。发送间隔先取 **1.2–1.5 s**（大约 3 倍），1000 包一轮约 20–25 分钟。这是下限：没算模块附加字节，串口的约 50 ms 和“两端各一次、每字节约 1.04 ms”也不完全一致（见硬件清单 2.8）。不因此另定一档间隔。到货后用 AUX 高电平时长修正。
8. **若 A 决定改用 LEVEL3（250 kHz，SF8）：** 32 字节空口约 62 ms，短于 LEVEL2（SF11）的约 206 ms，发送间隔不因此加长。LEVEL3 的发送间隔和 16 字节回执时间都是**待 AUX 实测确认**，本文不写这两个数。代价是接收灵敏度下降、距离变短；再加上功率 ≤10 dBm，覆盖范围明显缩小，适合近距离测试。1.2–1.5 s 只属于 LEVEL2 的理论起点。
9. 出厂功率和带宽相对上述公告超限。**待 A 决定**是否在测试前改配置。决定写下来之前，不做长时间连续发射。正式三轮（每轮至少 1000 包）属于长时间发射。

## 4. 执行步骤

1. 两节点上电。先把串口日志落到磁盘，再开始发送。
2. 读回两端模块配置，存进本轮目录，确认双方参数一致（LEVEL、信道、密钥开关、传输模式）。
3. 预实验：发 50 包，检查序号连续、没有积压，然后冻结 T。预实验单独保存，不并入正式三轮。
4. 正式第 1 轮：两节点**重新上电、各自独立启动**。TX 从序号 0 起连续发送 **至少 1000 个序号包**，间隔为冻结后的 T。
5. 最后一包发出后，再等至少 ___ 秒（取若干倍 \(T_{cycle}\)，冻结时写明具体秒数）作为观察截止，然后停止记录。
6. 第 2、3 轮重复第 4–5 步。每轮重新上电、使用新的 run_id，位置和参数不变。
7. 每轮结束检查日志是否完整。中途中断如实记录，不删除失败轮次。需要补测时另起 run_id。
8. 另一名成员按本文独立复现至少一轮，写下复现人和日期。

## 5. 接收端记录 RSSI/SNR

<a id="rssi-record"></a>

- RSSI/SNR 只由**接收端**在收到该包时记录，对应包序号。
- RSSI：执行 `AT+DRSSI1` 并 `AT+RESET` 之后，每个接收包末尾多 1 字节。RSSI = –(0xFF – 该字节) dBm，例如 0xAB → –84 dBm（应用指导 5.3.11）。解析时去掉这 1 字节；原始字节和换算值都保存。出厂默认是关闭的（`AT+DRSSI0`）。
- SNR：手册没有读取指令，按不支持处理（是否有未记载的指令，**待厂家确认**）。每包填 `null`，报告里写明这是模块限制。不补造数值。
- 每轮开始前用 `AT+ERSSI` 记一次当前信道噪声。
- 回执方向（RX→TX）如果也有 RSSI，另列记录，并标明方向。

> **待 A 决定：** 模块只能提供 RSSI。#3 验收里的 SNR 分布如何处理，由 A 决定。在决定之前，记录保持 `null`，不要为了表格填一个数。

## 6. 每轮结果统计

| 指标 | 定义 |
|---|---|
| 发送数 | TX 日志中实际发出的序号个数 |
| 唯一接收数 | RX 日志去重后的序号个数 |
| 缺号 | 0…最大序号中没有收到的序号 |
| 重复 | 同一序号收到多次的次数 |
| PDR | 唯一接收数 ÷ 发送数 |
| RSSI/SNR 分布 | 最小、最大、中位数、分位数或直方图。没有数据写 unknown。SNR 在本模块上按第 5 节填 `null` |
| RTT | 有回执时，由 TX 同一时钟测得的往返时间分布 |

近距工程目标：每轮 PDR ≥95%。达不到时先查接线、供电、参数、间隔和干扰。这个门槛不代表户外覆盖能力。
