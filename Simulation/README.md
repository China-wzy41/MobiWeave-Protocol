# Simulation — 把「存储-携带-转发」画出来

第二阶段 Demo。**不碰硬件**，用一份模拟出来的 V1 日志，证明三件事：

1. 孤岛之间确实直连不上（距离 > LoRa 半径）；
2. 消息能靠会走路的移动节点，一站一站带过去，最后送到；
3. 这条链路在界面上是**看得见**的——哪一秒谁收下了、走了几跳、哪条路断过。

界面长这样（`docs/shots/` 里有全部截图，都是 `SIM` 模拟数据）：

- 开局：三个孤岛 + 移动节点在岛上
- 携带中：消息躺在移动节点的口袋里，正在过地形阻隔
- 首次送达：金圈亮起，标注「#3 送达」
- 末段：两条长途消息也到了

## 30 秒跑起来

需要 Python 3.10+ 和 tkinter（标准库自带），**不需要 pip 装任何东西**。

```bat
cd Simulation

python -m visual.simulate --scenario hiking --out sim      :: 重新生成一份日志
python -m visual.mapview                                   :: 打开地图回放
```

`mapview` 默认读 `sim\trace.jsonl` + `sim\log.jsonl`，直接回车就是徒步场景。
换场景：

```bat
python -m visual.mapview --dir sim-inspection    :: 偏远巡检
python -m visual.mapview --dir sim-lab           :: 高校实验
```

想从第 300 秒开始看：`--t 300`。

## 三个场景

| 场景 | key | 时长 | LoRa 半径 | 孤岛间距 | 一句话 |
|---|---|---|---|---|---|
| 户外徒步：山谷把队伍切断，驴友互相捎话 | `hiking` | 900 s | 160 m | 400 m | 7 条消息，15 分钟内送达 6 条 |
| 偏远巡检：一条巡检线，几个打卡点，巡检员沿线走 | `inspection` | 1200 s | 150 m | — | 巡检员本身就是移动节点 |
| 高校实验：两个实验室不能直连，同学拿板子跑一趟 | `lab` | 600 s | 120 m | — | 最小可复现的版本，适合答辩 |

三个场景用的是**同一套固件、同一套日志格式**，只是配置不同。这正是产品定位：
一套代码，三种用法，靠配置切换。

## 界面怎么看

左边侧栏：

- 顶上写场景标题，下面是 `⚠ 模拟数据：轨迹与消息由 simulate.py 生成，非真实链路`
  ——**别把模拟轨迹当成真实定位**；
- `T = xxx s` 当前回放时间；
- 运行状态：活跃链路几条（以及 LoRa 半径）、已交付 / 总数、在途几条、节点数；
- 图例：`青绿虚线 = 可达链路`、`橙点 = 移动节点`、`白方块 = 固定节点`、`金色圈 = 消息送达时刻`；
- 最近事件：最近 8 条消息的编号、源→目的、类型，以及「已送达」还是「在途」。

底部：`▶ 播放` / `重置` / `速度 4x`（点一下升一档）/ 进度条 / `打开日志…`。

地图上：

- 两条深色竖带标着「地形阻隔」——示意断崖/河谷，它才是直连不上的真正原因；
- 青绿虚线是**当前这一帧仍然可达**的链路，节点走远了线就消失；
- 移动节点走到哪，它就带着哪些消息——消息不是"飞"过去的；
- 送达那一刻会亮一个金圈并标注编号。

## 和 `Host/` 是什么关系

两个目录吃的是**同一份 V1 日志格式**，分工不同：

| | `Host/` | `Simulation/` |
|---|---|---|
| 输入 | 真实串口/文件日志 | `simulate.py` 生成的模拟日志 |
| 关心什么 | 一条消息的完整事件链、状态判定对不对 | 消息在地理上怎么流动、多久送到 |
| 界面 | 节点表 / 链路表 / 消息表 + 事件链下钻 | 地图回放 + 时间轴 |
| 依赖 | 零第三方 | 零第三方（`tools/shoot_map.py` 例外，见下） |

所以：**先用 Simulation 讲清故事，再用 Host 验证真数据**。真实日志接进来时，
`Host/` 一行不用改；`Simulation/` 只要把 `--dir` 指到真实 trace 也能回放。

> 注意：V1 日志里**没有位置字段**。位置走的是旁路 `trace.jsonl`（每 5 秒一帧）。
> 这是刻意的——板子上没有 GPS，硬把位置塞进 V1 会污染协议。

## 已知限制（别在答辩时被问住）

- **位置是模拟的**，不是实测 GPS。界面上有 `SIM` 标记，说的时候要主动讲清；
- 单条消息最长要接近 15 分钟才送达——这是 store-carry-forward 的**真实代价**，
  不是 bug。讲的时候主动解释"为什么慢"：不是链路慢，是**得等人走过去**；
- 转发策略是最朴素的 **epidemic**（见面就换、人人存副本），副本数会随节点数涨，
  规模上去必须加 TTL 和副本上限；
- 空口速率 2149 bps（LEVEL=2），一条 39 字节帧约 0.15 s——链路上说话的机会很有限；
- 地图是**示意图**，不是真实地图瓦片。好处是断网也能演示，坏处是不能拿来做导航。

## 自动截图（可选）

```bat
python -m pip install pillow
python visual\tools\shoot_map.py
```

会依次打开三个场景、各截几帧到 `docs\shots\`。**只有这个脚本需要 Pillow**，
主程序不需要——演示机上没装 Pillow 也照样跑。
