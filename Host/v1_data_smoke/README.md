# DATA/CRC 与本跳 ACK 实验

这是未冻结 v1 草案的主机实验工具。可靠发送只确认**本跳缓存接纳**，不表示最终应用已经交付，更不表示端到端成功。模拟、真实串口和 LoRa 空口是三件事。2026-11-18 21:22 已停止实物测试，**没有做过 ACK 的无线实测**。

两端电脑各运行一份。先关掉 Arduino 串口监视器，把 COM 口让出来。LoRa USB 桥保持原样，不要改固件。

模块必须已经退出 AT、处在透明传输。本工具不发送任何 AT，也不删掉末尾字节。不要把两台电脑的时间相减成单程延迟，日志不记 SNR。

## 与草案不一致的地方

这些是本工具的边界，草案原文没有改。

- 草案仍把 ACK 超时、重试上限和退避标成待确定。下面的数字只是本工具实验默认。
- 草案把去重记录保留时间标成后续定义。本工具把记录留到本地年龄达到 `lifetime_ms`，并且不超过缓存条数。过期后不再回复 ALREADY_HAVE。
- 草案允许中继。本程序不转发。下一跳是本机但最终目的不是本机时，不入缓存，也不回 ACCEPTED 或 ALREADY_HAVE。
- 删掉整个 `state/node-<id>/` 目录后，工具无法把它和第一次安装分开，会再次从 boot=1 开始。不要删这个目录。目录还在、但 `boot` 文件损坏或丢失时，拒绝创建新消息。
- 同一节点目录用 `boot.lock` 的独占创建互斥，Windows 和 Linux 都走 `O_CREAT|O_EXCL`，不用 fcntl。锁已被占用或写入失败就拒绝分配。进程崩溃或突然掉电可能留下锁文件，也可能使目录项尚未落盘；这时下次会拒绝分配，或在文件损坏时拒绝。成功返回并读回的编号不会在持锁期间被另一个进程再发出一次。这不是掉电后的绝对唯一证明。Linux 会再同步目录；Windows 上这次运行同步不了目录项。

## 实验默认

| 项目 | 值 |
|---|---|
| 本跳 ACK 超时 | 3000 ms |
| 超时后再重试 | 2 次（连同第一次，最多写出 3 次） |
| 超时退避 | 1000 ms |
| 对端 BUSY 后再试 | 2000 ms |
| 缓存条数 | 16 |
| 消息寿命 | 60000 ms |
| 直达跳数上限 | 1 |
| 解析空闲 | 1 s |

重传使用原 `(source, boot, sequence)`，年龄按本地时钟增加且不回绕，同一跳的 hop 不加。ACK 本身不再要 ACK。坏长度、坏 CRC 不回复 ACK。未知 status 不算成功。缓存满是 BUSY，过期是 EXPIRED，两者不是一回事。

## Windows 步骤

1. 安装 Python 3.10 或更新版本，并加入 PATH。
2. 进入本目录。
3. 安装依赖：`py -3 -m pip install -r requirements.txt`。若官方源 TLS 中断，可改用清华 HTTPS 镜像，不要关闭证书校验。
4. 启动：`py -3 v1_smoke_gui.py`
5. 刷新并选择 COM，选择节点 1 或节点 2，再连接。连接期间不能改节点。
6. “发一条短消息”只发一次，不自动重传。
7. “可靠发送”会等待本跳 ACK，并按上表有限重试。窗口里的“本跳缓存确认”仍然写着端到端未知。
8. “发送坏 CRC 测试帧”应被拒收，且不回复 ACK。它不计入唯一收包，也不当成无线丢包。
9. 日志在 `logs\<run_id>\`。`*-rx-chunks.txt` 的一行是一次 read，不是一帧。

启动计数写在 `state\node-<节点>\boot`。同一次进程里断开再连接不会加 boot；下次启动进程才会加一。同一目录同时只能有一个进程分配编号。序号从 1 递增，满了就停止，不回绕。存储写失败、锁冲突或计数文件损坏时不会发出可能重复的新编号。

统计只保留最近 64 条唯一收下（缓存条数的 4 倍）。序号空洞只在这些仍保留的编号上按区间摘要，不逐个展开，不跨 boot，也不把坏 CRC 算进去，不能当成丢包率。待发和已结束记录合计不超过缓存条数。RTT 只用本机从完整写出到收到匹配 ACK 的时间，最多保留 16 条，不是单程。没完整写出过的排队或短写不能被 ACK 提前确认。

打开串口时会尽量拉低 DTR 和 RTS。有的板子仍会重启。短写或异常会记下实际字节和 `complete=no`，不会显示整帧已发送。断开、关闭窗口会停掉待发和定时重试，不会一直重传。

自动化测试不打开串口，也不代表空口已经测过：

`py -3 -m unittest discover -s tests -t .`
