# DATA/CRC 冒烟测试

这是未冻结的 v1 草案冒烟工具，只发送和检查 DATA 帧的长度与 CRC。没有 ACK，没有重传，没有缓存，也没有去重。不能把它当成可靠协议已经通过，更不能当成 LoRa 无线已经测通。

两端电脑各运行一份。先关掉 Arduino 串口监视器，把 COM 口让出来。LoRa USB 桥保持原样，不要改固件。

模块必须已经退出 AT、处在透明传输。首轮不要在数据末尾附加 RSSI。项目摘录的 `AT+HELP` 示例里没有 DRSSI 行；开关以厂家手册里的 `AT+DRSSI` 为准。本工具不发送任何 AT，也不自己删掉最后一个字节。两端 LEVEL 和信道需已经相同。用户已报告读回 MODE0、LEVEL3、SLEEP2、434.15 MHz/CH01、10 dBm，那是用户侧证据，不是本程序核实的。

## Windows 步骤

1. 安装 Python 3.10 或更新版本。安装时勾选 “Add python.exe to PATH”。
2. 打开“命令提示符”。
3. 进入本目录，例如 `cd C:\path\Host\v1_data_smoke`。
4. 安装唯一的外部依赖：`py -3 -m pip install -r requirements.txt`
5. 启动：`py -3 v1_smoke_gui.py`
6. 点“刷新”，选择本机 COM，选择节点 1 或节点 2，再点“连接”。另一台电脑选另一个节点。
7. 节点 1 输入短文字，点“发一条短消息”。到节点 2 的窗口看“有效帧”。再反向发一次。
8. 点“发送坏 CRC 测试帧”。对端应显示“拒收 坏 CRC”，而不是有效帧。
9. 日志写在本目录 `logs\<run_id>\`。`*-rx-chunks.txt` 里的每一行是一次串口 read，不是一帧。

发送端窗口不会回显自己刚发出的字。看不到自己的字不是失败。

打开串口时会尽量拉低 DTR 和 RTS。有的 USB 芯片仍可能在打开端口时复位 ESP。若板子重启，等它回到透明传输再发。本工具不会补发 AT，也不会改射频。

默认不连续发送，也不自动回复。解析器若 1 秒没有收齐一帧就放弃，这是本工具的实验默认，不是草案里已经冻结的超时。

两台电脑的时钟不能相减成单程延迟。日志不记 SNR。

编码按 `docs/protocol/protocol-v1.md`：源地址是本节点，下一跳和最终目的都是对端。本工具只做直达，不做转发。最终目的不是本节点时，即使下一跳是本机，也显示拒收，不能标成有效本地交付。文档里最终目的为 3 的 SOS 样例因此不能在节点 2 上当成有效帧。

`boot_counter` 固定为 1，只用于这次独立冒烟。它不是掉电保存的启动计数，不保证跨重启唯一编号。本工具没有 ACK，也没有去重。`sequence` 只在本次进程内、整帧被串口完整接受后才加一。若 `write` 只写出一部分或抛出异常，日志记实际接受字节和 `complete=no`，窗口不会显示整帧已发送。

连接期间不能改节点。断开时先停读线程并等待它退出，再关闭串口和日志。重连使用新的端口、日志和解析器，不把上一会话的事件记到新会话。

自动化测试不打开串口：

`py -3 -m unittest discover -s tests -t .`
