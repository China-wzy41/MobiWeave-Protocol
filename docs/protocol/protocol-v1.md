# MobiWeave 通信协议 V1 草案

状态：讨论稿，尚未冻结，尚未完成代码验证。

## 1. 目标与范围

硬件：ESP32-S3 N16R8 + DX-LR22-433T22D。
开发环境：Arduino。

第一阶段实现短消息的编码、解析、校验、确认、有限重传和去重。
本阶段先定义消息与日志格式，为硬件、仿真、上位机提供共同接口。
分片与断点续传在后续阶段设计。

## 2. 协议帧需要定义的内容

以下为候选内容，最终字段布局、类型和长度待讨论。

| 内容 | 含义 | 待确定事项 |
|---|---|---|
| 帧边界 | 从串口字节流中识别完整报文 | 帧头、转义或其他编码方式 |
| 协议版本 | 区分不同版本的报文 | 字段长度、未知版本处理 |
| 帧类型 | 区分数据帧与 ACK 等控制帧 | 类型编号 |
| 长度 | 判断报文是否完整和是否合法 | 计数范围、最大长度 |
| 本跳发送与接收节点 | 标识当前无线传输的双方 | 地址格式 |
| 消息源与最终目的节点 | 标识消息最初来源与最终去向 | 地址格式 |
| 消息唯一编号 | 用于追踪、去重和确认 | 重启后不重复的生成方案 |
| 优先级 | 决定消息发送顺序 | 等级、同级排序与防饥饿规则 |
| 消息年龄与有效期 | 判断消息是否过期 | 单位、计时和跨节点更新规则 |
| 已用跳数与跳数上限 | 限制转发次数 | 增加时机与边界判定 |
| 业务载荷 | SOS、位置或文字等内容 | 编码与最大长度 |
| CRC | 检查报文完整性 | 算法、参数、覆盖范围和字节序 |

## 3. 基础收发流程

1. 发送节点创建消息并分配唯一编号。
2. 检查有效期、跳数限制和队列容量。
3. 编码并发送数据帧，启动 ACK 等待计时。
4. 接收节点完成帧解析、长度检查和 CRC 校验。
5. 校验通过后，检查消息是否重复。
6. 根据接收结果返回对应状态的 ACK。
7. 发送节点根据 ACK 更新状态。
8. 超时后有限重试，达到上限后记录失败原因。

待确定：ACK 字段、超时依据、重试上限和退避规则。

## 4. 确认状态

必须区分：
- 本跳接收成功。
- 已持久保存。
- 目的应用最终交付。

第一版普通 ACK 的准确语义待确定。
未实现持久化时，不得声称已经持久保存。
中间节点的 ACK 不代表最终目的节点收到。

## 5. 异常处理

| 情况 | 需要明确的行为 |
|---|---|
| 长度不合法 | 丢弃与重新寻找帧边界的规则 |
| CRC 错误 | 丢弃、日志和是否响应 |
| 半帧 | 等待后续字节及解析超时 |
| 重复消息 | 不重复交付，是否再次回复 ACK |
| ACK 超时 | 重试、退避和最终失败状态 |
| 队列已满 | 拒绝或淘汰规则及反馈 |
| 消息过期 | 停止发送和清理规则 |
| 节点重启 | 编号、缓存和去重状态如何恢复 |

## 6. 日志格式

日志与无线报文分别定义，不要求把全部日志字段通过无线发送。

候选日志字段：
- format_version：日志格式版本
- run_id：实验编号
- source_kind：REAL / SIM / ESTIMATED
- code_version、config_version、strategy_version：版本信息
- node_id：产生日志的节点
- message_id：关联消息
- monotonic_ms：节点本地单调时间，单位毫秒
- event：创建、发送、接收、缓存、转发、交付、丢弃或失败
- result、reason：结果与原因

不同节点的本地时间不能直接当作已经同步。
未测量的 RSSI、电量和位置使用 null 或明确的未知值。
