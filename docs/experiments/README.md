# 实验与验收方法｜C 主责，各方向配合

这些是待执行的验收方法与研究目标，不是已经取得的结果。任务卡只保留关键步骤，细节以这里为准；正式试验前冻结版本与指标。

## 所有实验先保存这些

每次独立运行使用一个 run_id，保存代码/固件/模型版本、参数、消息生成规则、随机种子、环境、开始结束条件、原始日志和分析输出。模拟、实物、估计分开记录；失败和过期不能从数据中删除。

运行说明必须让另一成员找到输入、命令、预期输出和实际输出。每轮观察到最后一条消息的截止期；提前停止须说明未完成观察如何处理。原始数据不覆盖，修正分析另记版本。

## M0：无需 LoRa 的四类案例

正常、丢包、重复、断链四类都要可复现；再覆盖丢 ACK、延迟、重连。固定种子与配置，提供小规模人工可核对样例。统计发送数、唯一接收数、缺号和重复，解释分母和去重口径。

提供可配置 1000 包的输入、发送间隔、结果导出和真实无线记录模板。模拟测量值标 SIM，不用于证明无线性能。另一成员复现案例，D 能读取同一份日志。对应 [#8](https://github.com/China-wzy41/MobiWeave-Protocol/issues/8)、[#20](https://github.com/China-wzy41/MobiWeave-Protocol/issues/20)。

## M1：双节点无线基线

1. A 核对实际芯片/模块官方资料、供电、接口、引脚、天线、频段、收发能力和可读元数据。核对实验地点适用的射频使用约束，未知项不猜。
2. 固定近距布局，记录 SF/BW/CR、功率、载荷、发送间隔、设备和环境。数据与 ACK 的空口时长都要考虑，不能高速灌包后把队列溢出算成无线损失。
3. **独立启动三轮，每轮至少 1000 个带序号数据包。** 记录发送数、唯一接收数、缺号、重复、包级 PDR 和接收端 RSSI/SNR 分布；不支持元数据的模块注明限制并调整采集方案。
4. 近距固定条件的工程目标是**每轮 PDR ≥95%**，未达标先定位。此门槛不代表户外覆盖或远距离保证。
5. 未同步设备先报告同一时钟测得的 RTT；不能直接相减两设备时间戳声称单向延迟。由另一成员复现实测。

对应 [#3](https://github.com/China-wzy41/MobiWeave-Protocol/issues/3)。最远距离测试后置，必须报告地形、天线、参数和成功率。

## M1：可靠传输与三节点携带

可靠传输测试覆盖正常、丢数据、丢 ACK、重复、乱序/延迟、重启序号六类情况。有限重试，不无限重传；应用不重复交付；失败原因明确。可靠传输成功率和裸链路 PDR 分开计算。先模拟，再在无线基线通过后运行同类实物用例。对应 [#10](https://github.com/China-wzy41/MobiWeave-Protocol/issues/10)。

三节点称为**源节点 S、携带节点 M、目的节点 R**，避免与人员角色 A/B 混淆。S 与 R 不可直接通信；M 先接触 S，彻底断开后再接触 R，不能同时存在端到端通路。记录接触起止、创建、缓存、携带、转发和最终交付事件。上位机只采集日志，不能通过 USB/Wi-Fi 暗中跨区传业务消息。受控开关接触与真实移动分别标注，保留连续录像。先做单帧短消息。对应 [#11](https://github.com/China-wzy41/MobiWeave-Protocol/issues/11)。

完整验收见 [#13](https://github.com/China-wzy41/MobiWeave-Protocol/issues/13)：

- **20 轮独立流程，每轮 5 条固定编号消息，含高优先级消息**；每轮重置相同初态，观察至截止期。
- 工程目标：至少 **18 轮全部完整交付，应用重复交付为 0**。保存所有 20 轮结果；100 条消息不是 100 次独立重复。
- 过期、缓存满、重启、丢 ACK 各至少 **3 次**；缓存容量、持久化成本、淘汰原因和确认语义明确，重启不能刷新消息寿命。模拟和实物结果分开。
- 另一成员按说明复现，交原始日志、配置、脚本、报告与 2–3 分钟演示。

这是工程验收，不能凭此宣称预测策略有统计优势。对应缓存任务 [#12](https://github.com/China-wzy41/MobiWeave-Protocol/issues/12)。

## M2：短接触窗口与固定基线

分片/重组、位图或选择性 ACK、断点续传、完整性校验和有限缓存先稳定。空口预算包含握手、确认、重传和遥测。至少做 **3 档接触窗口 × 2 档负载**的冒烟试验，并单独比较分片/确认机制的影响；为 M3 保存真实事件记录。

在同一 DTN 底座切换策略，不能故意削弱 FIFO：

|策略|含义|
|---|---|
|B0|按到达顺序发送（FIFO）|
|B1|固定优先级，同级规则预先冻结|
|B2|简单接触窗口估计与传输预算|
|P|轻量预测、自适应预算和失效回退|

无 DTN 的方案可以说明断链问题，不能作为证明预测创新的唯一对照。对应 [#14](https://github.com/China-wzy41/MobiWeave-Protocol/issues/14)。

## M3：数字孪生要有验证

1. 用同一组 ID 映射节点、接触、消息/分片和队列；缺失或陈旧状态显示未知与最后更新时间。
2. 用实物数据校准空口时间、链路成功率、接触持续时间与队列行为，记录模型版本及适用范围。
3. 同一事件记录、配置和种子能够回放；核对事件顺序与时间对齐。
4. 比较新策略时保留相同外生接触和消息生成条件，但重新计算发送时序、竞争、ACK 与丢包；不能沿用旧策略的成功标签。
5. 校准集与留出实验按运行和日期隔离，比较交付率、延迟分布、队列/空口占用和策略排序。暂定主要交付率绝对误差目标 **≤10 个百分点**，正式留出测试前冻结，报告误差范围和失败场景。
6. 至少完成一次“虚拟选策略 → 影子运行 → 实物执行 → 数据回传”。节点离线仍能执行本地固定规则。

只有拓扑或回放界面时称监测/回放平台或孪生原型，不能当作已完成可信孪生。C 负责模型和验证（[#15](https://github.com/China-wzy41/MobiWeave-Protocol/issues/15)），D 负责展示（[#22](https://github.com/China-wzy41/MobiWeave-Protocol/issues/22)）。

## M4–M5：怎样判断预测有用

先选一个预测目标，比较常数或 EWMA 等简单规则与一种轻量模型。只使用决策时实际可获数据；真实未来窗口只能作离线上界，不能进入在线输入。

训练、校准、验证与最终测试按运行、日期、路线分组隔离，不能把同次移动的相邻数据随机分到训练和测试。记录端侧推理时间、RAM/Flash 和控制/遥测开销；不确定或状态过期时回退固定规则。

**主指标：**高优先级按时完整交付率 = 目的应用在截止期内完整重组、校验通过且首次交付的高优先级消息数 ÷ 本轮产生的全部高优先级消息数。未交付、淘汰和过期都计失败。

同时报告全部消息交付率、已交付消息延迟分位数及未交付比例、有效载荷/总空口时间、确认/重传/遥测开销、缓存峰值、普通消息饥饿、推理成本。无电流电压测量时只报告收发时长或估算，不能称实测能耗；共同时间线须说明同步误差。

消融每次只去掉一项：预测、优先级、自适应预算或回退。保持协议、缓存与可靠性底座一致，避免混淆收益。

M5 选择 **3 类代表场景**。仿真每条件至少 **20 个独立种子**起步；实物每关键条件至少 **10 轮、跨 3 个测试日**。按预实验方差、效应量和区间宽度补足。以独立运行作为统计单位；相同路线与负载配对，随机或交替策略顺序，记录环境漂移。

暂定争取目标：P 相对强基线 B1 的主指标提高 **≥10 个百分点**，总空口开销增加 **≤15%**，普通消息交付率下降 **≤5 个百分点**。这些不是已证明结果。正式测试前冻结，报告 **95% 置信区间**和无效区域；不能看完测试结果再换口径。无收益也保留结果与适用边界。对应 [#16](https://github.com/China-wzy41/MobiWeave-Protocol/issues/16)、[#17](https://github.com/China-wzy41/MobiWeave-Protocol/issues/17)。

## 应用与展示的证据

E 访谈 3–5 名有相关经验者，记录消息类型、允许延迟、谁携带、为何不能依赖公网、部署维护限制；映射到协议和验收指标。只公开匿名摘要，访谈不等于采购或正式合作。

M6 在一个获同意的受控场景试用，记录部署时间、错误、供电续航、成本、维护与改进前后。处理实际发现的身份、隐私和数据保存问题；校园试验不等于真实灾害认证。6–8 节点只在预算与主线允许时扩展。

M7 交付固件、上位机、孪生工具、数据与脚本、版本、报告、视频和答辩材料。非原开发者独立复现；5 分钟演示包含断链、携带、恢复和同条件策略对比。备用节点/电源明确，离线回放必须标注。所有主张能追溯到原始证据。
