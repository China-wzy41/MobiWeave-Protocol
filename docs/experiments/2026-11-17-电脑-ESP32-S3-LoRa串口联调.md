三、已完成的工作与观察
1. ESP32 串口桥接
已烧录并运行 Arduino 双向逐字节转发程序。
电脑侧 Serial：115200；模块侧 UART1：9600、SERIAL_8N1。
代码引脚：GPIO18 为 RX，GPIO17 为 TX。
对应连接：模块 TXD→GPIO18，模块 RXD→GPIO17，VCC→供电，GND→共地。
使用开发板 COM 接口；可看到启动日志与桥接就绪信息。
断开模块，短接 GPIO17/18 后发送 hello123，可原样收到，ESP32 桥接回环通过。
这只证明回环数据路径，不证明带模块时供电或模块工作正常。

2. 欠压现象与测量纠正
尝试改用开发板 3V3 给模块供电后，截图出现 rst:0xf (BROWNOUT_RST)。
这是 ESP32 欠压复位信息，不是模块 AT 回应；模块脱离后反馈不再重启。
万用表照片曾发现红表笔插在电流孔；随后改为红笔 VΩ、黑笔 COM。
纠正插孔前的电压读数不用于判断模块好坏。
两根供电线分别做断电通断测试，均导通；表笔互碰显示约 0.0Ω。
导通通过不等于带载时压降合格。

3. ESP32 供电路径测量（插孔纠正后的记录）
模块完全断开时，开发板 5V-GND 空载约 4.68V。
接模块仅供电时，模块端约 0.5V，板端也约 0.5V。
更换 USB 数据线后，连接模块时板端与模块端均约 1.8V。
随后拆下模块所有线，仅 ESP32 空载，新线测得 4.67V。
结论限于：接入模块后发生明显供电压降；换线没有解决。尚不能认定模块损坏。

4. 模块断电电阻对照
两只同型号模块分别完全断开，在 200Ω、2kΩ 档测 VCC-GND，均显示 OL。
OL 表示超出当前量程/未测到导通，不是 0Ω；不能据此认定模块正常，也不能排除上电后异常电流。
两只模块均做过的是断电电阻对照，不是两只均已完成相同的上电串口测试。

5. PJ15 转接板供电与接口线索
PJ15 空载：5V-GND 为 5.08V；用户澄清 TX-GND 空闲电压为 3.3V。
经原母座连接模块供电时，模块端曾仅 0.08V。
后来绕过母座，将线直接连接 PJ15 引脚，再连接模块，用户测得模块端约 5V。
这提示母座接触、焊接或针位映射存在问题的可能，但没有确定具体故障点。
PJ15 背面有两组不同针序标记，不能将不同排的标注直接混用，也不能把 VCC 误读为 NC。
空载或仅接供电时电压正常，不代表完整四线连接时也正常。

6. PJ15 串口测试
Arduino 串口监视器截图：COM8、9600、“没有结束符”；COM8 是当时使用的端口，重插后应重新确认。
开发板型号选择影响编译/烧录；直接使用 PJ15 时，不需给 PJ15 烧录 ESP32 程序。
PJ15 自身 TX/RX 短接，发送测试文字能收到，回环通过。
再使用实际两根信号线，在原本接模块的远端短接，同样能收到，带线回环通过。
