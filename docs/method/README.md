# 怎么验证

计划见 [长期计划](../planning/长期计划.md)。下面是要做的核对，不是已经取得的徒步链路结果。

## 整条链路

还要做出来并实地测试：

手机取得坐标 → 低功耗蓝牙（BLE）→ 本机无屏节点 → LoRa → 队友节点 → 队友手机显示

手机取坐标、BLE、本机节点、LoRa、队友节点、队友手机显示，每一段都还没有实现，也还没有验证。没有蜂窝网络时，手机仍可能取得卫星坐标；权限、冷启动和天空遮挡尚未测试。

每一段单独记录输入、输出和失败。地图瓦片留在手机上，不走 LoRa。模拟、实物和估计分开写。失败和过期的记录不删。原始日志不覆盖。

## 已有的串口记录

[工程日志](../ProjectLog/A_wzy/2026-11-17-电脑-ESP32-S3-LoRa串口联调.md) 和 [板1、板2](../../Firmware/hardware/2026-11-17-ESP32-LoRa成功板记录.md) 只记录 2026-11-17 的串口 AT，不是上面任何一段。

两块 ESP32 上完成了 Entry AT、AT OK 和 AT+HELP。PJ15 只给 LoRa 供 5V，ESP 用自己的 USB，两边共地。模块 TXD→GPIO18，RXD→GPIO17。M0、M1 没接。USB CDC On Boot 为 Disabled。电脑 115200，LoRa 9600 8N1。

第三套稳定启动、电台参数写入与读回、RSSI 采集、别人独立复现，都还没有。读回仍是 LEVEL2、433.15 MHz 信道 00、22 dBm。不记录 SNR。第三套循环重启的记录保留。

## 轻量延迟容忍

缓存要有上限。消息要有存活时间，转发和重传不能把寿命清零。断连时先保存，再在下一次接触时送出。确认、重试、去重、转发和多跳各自还要证据。日志里出现这些事件名，也不等于板上已经做到。

日志校验、统计、回放和实验设计由 C（ygh）负责。数字孪生不在当前交付里，不排成后期承诺，也不永久取消。

## 外场前的电台核对

任何户外或外场使用之前，先核对适用的工信部规定，再配置 LoRa。要核对频段、设备类别和用途、设备条件、带宽和发射时长、天线，以及型号核准或豁免是否适用。

这是前提。系统还没有完成这项核对，不写已经合规。降低功率、433 MHz 遥控类规定和 22 dBm，都不能自动使徒步文字、位置或多跳使用合法。
