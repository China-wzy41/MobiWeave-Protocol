# 1. 执行摘要

本报告围绕“织网行动”项目，评估全球应急通信及断连环境下关键消息传输的市场需求、细分场景、客户采购逻辑、竞争格局、采购证据、商业化路径与主要风险。项目拟采用 LoRa 通信节点、轻量化延迟/容忍网络（DTN）机制与数字孪生平台，面向基础通信设施不可用、节点移动且网络间歇连接的环境，补充传输求助、位置、告警及设备状态等短消息。

核心结论：应急通信存在持续的社会需求和实际采购行为，但现有公开数据不足以直接计算“LoRa-DTN 应急消息系统”的全球市场规模。织网行动不宜定位为卫星、蜂窝或专业宽带 Mesh 的替代品，而应聚焦断连保存、移动携带转发、短接触窗口调度和最终交付确认等差异化能力。

| **判断维度** | **结论** | **对团队的含义** |
| --- | --- | --- |
| 需求真实性 | 强。灾害影响人口、基础设施损坏和公共服务中断数据支持应急通信需求长期存在。 | 市场背景成立，但灾害损失不能直接换算为通信设备市场收入。 |
| 付费意愿证据 | 存在。美国DHS、澳大利亚消防部门及中国应急部门均有相关通信设备或服务采购记录。 | 应重点研究政府采购流程、系统集成商渠道及可靠性要求。 |
| 竞争强度 | 中高。已有专用Mesh、MANET、卫星通信和LoRa Mesh产品。 | 必须通过断连携带转发、续传、短窗口调度和可验证数据建立差异。 |
| 产品成熟度 | 项目处于研发验证规划阶段，首年目标为4—8节点原型和二维数字孪生平台。 | 当前不应承诺真实救援部署、认证能力或商业化性能。 |
| 市场规模 | 无法用现有公开数据得出可信的单一TAM数字。 | 采用客户数量×单套价格的自下而上测算。 |

## 关键决策建议

- 短期优先面向高校/科研实验室、移动机器人研发团队、野外巡检团队和应急通信集成商，先形成可复现实验与科研/演示套件。
- 以断连携带转发、分片续传、最终交付率、时延、功耗和短窗口调度效果作为核心证据，不以 LoRa 低成本或厂商标称距离作为唯一卖点。
- 市场规模采用自下而上的 TAM/SAM/SOM 模型；在客户数量、节点数、价格和转化率获得可靠输入前，不发布单一全球市场规模数字。
- 首年目标应是建立可信技术证据，而不是承诺真实救援部署、认证能力或规模化销量。

# 2. 研究目的、范围与定义

## 2.1 研究目的

本研究用于支持挑战杯项目的市场定位、首发细分市场选择、竞争分析、商业模式设计和后续验证计划。重点回答：目标问题是否真实存在、哪些客户可能首先采用、现有方案如何满足需求、采购证据能说明什么，以及项目下一阶段需要补齐哪些市场与技术证据。

## 2.2 研究范围

- 地域范围：全球市场作为行业观察范围，重点案例来自美国、澳大利亚、中国和挪威等公开采购记录涉及地区；这些案例不代表全球市场份额。
- 产品范围：基于 LoRa 的低速关键消息传输节点、轻量化 DTN 协议与数字孪生验证平台。
- 应用范围：自然灾害与应急救援、森林/山地及偏远巡检、矿山/隧道及地下空间、人道主义援助与临时营地、移动机器人/无人系统、高校与科研实验室。
- 商业范围：硬件、软件授权、部署集成和技术服务；不将整个卫星通信、物联网或数字孪生行业规模直接视为项目市场。

## 2.3 产品定义与系统组成

织网行动拟构建一套面向固定通信设施不可用、节点移动且经常断连环境的低成本 LoRa 关键消息传输系统。节点在相遇时交换消息，在失联时保存消息，再由移动节点携带至下一处接触点继续转发。

| **组成** | **计划实现内容** | **市场价值** |
| --- | --- | --- |
| 通信节点 | ESP32 + UART LoRa 模块、天线与电源；负责缓存、分片、调度和转发。 | 低成本、低功耗、可部署的本地通信节点。 |
| 轻量化DTN | 消息缓存、TTL、去重、分片续传、逐跳确认与最终交付确认、受限副本转发。 | 在没有持续端到端链路时仍争取完成消息交付。 |
| 短接触窗口调度 | 结合优先级、有效期、剩余字节数、完成比例和估计接触预算安排发送。 | 在短暂相遇时优先传输最重要且仍有用的消息。 |
| 数字孪生平台 | 实体节点映射、事件回放、链路模型校准、策略比较与实物反馈。 | 帮助解释通信过程、复现实验并验证参数选择。 |

## 2.4 产品边界与关键术语

- 适用业务：短消息、低速状态同步、求助与告警、位置上报、巡检异常信息。
- 非目标业务：视频、大文件、持续语音和宽带数据业务；项目不应宣称替代蜂窝网络、卫星通信、专业数字集群或大型 MANET。
- DTN（Delay/Disruption Tolerant Networking）：在端到端链路不持续可用时，通过存储、携带和转发机制争取完成消息交付。
- Store-Carry-Forward：节点暂存消息，并在后续遇到可通信节点时继续转发。
- TAM/SAM/SOM：分别表示理论可寻址市场、可服务市场和可获取市场。

首年计划完成 4—8 个节点、固件与协议、二维数字孪生平台、可重复实验数据和演示系统；相关验收数值属于计划目标，不是现有实测成绩。校园或可控开阔区域实验不能直接代表真实救援部署能力。

# 3. 方法与数据来源

## 3.1 研究方法

- 二手资料梳理：整理国际组织、行业联盟、企业产品资料、政府采购平台、招标公告和技术标准/研究资料。
- 案例比较：将专用 Mesh、MANET、LoRa Mesh、卫星终端及传统应急通信采购案例放在同一应用需求框架下比较。
- 客户需求分析：依据典型客户角色、使用场景、购买动机和采购关注点形成客户画像；该画像属于研究假设，仍需访谈验证。
- 自下而上市场测算：采用目标单位数量、部署套数、合同金额和可服务比例构建 TAM/SAM/SOM，不直接套用相邻行业市场规模。
- 风险与情景分析：结合产品成熟度、法规准入、性能不确定性、采购周期和交付能力提出保守、基准、积极三类情景。

## 3.2 数据来源类型

报告使用的数据主要来自 UNDRR、CRED/EM-DAT、ITU、LoRa Alliance、企业官网与产品规格资料、USAspending、Buy NSW、中国政府采购网、TED、Cherokee Nation 招标文件、SBIR.gov 以及 IETF RFC 9171 等公开来源。具体出处见附录 A。

## 3.3 数据质量与研究局限

- 本版本以公开二手资料研究为主，尚未完成 5—10 家潜在客户的一手访谈，也没有真实客户试点或项目成交数据。
- 不同地区采购制度、合同口径、税费、交付范围和币种不同，金额仅按原始公开记录表述，不进行未经说明的汇率换算。
- 采购案例包含 Mesh、卫星通信、框架协议、招标需求和研发资助等不同性质，不能混为项目产品销售额。
- 厂商公布的重量、续航、距离和节点能力属于厂商声明，不等同于独立测试结论。
- 市场规模输入仍需通过目标客户清单、供应商报价、客户访谈、法规核查和试点转化数据补齐。

# 4. 市场概览与规模

## 4.1 灾害与基础设施中断带来的需求背景

UNDRR 仙台框架监测数据指出，2016—2025 年全球平均每年约有 1 亿人受到灾害影响；同期记录到 92,947 处关键基础设施单位/设施受损或被毁，基本公共服务中断超过 160 万次。[1] EM-DAT 年度报告显示，2025 年记录 358 起自然灾害，造成 16,607 人死亡、约 1.102 亿人受影响，经济损失约 169.68 亿美元。[2]

上述指标说明灾害和关键基础设施中断具有全球性，但它们衡量的是灾害风险和社会影响，不是应急通信设备市场收入。

## 4.2 应急通信体系与 LoRa 生态

ITU 指出，在成员国请求后，可在灾害发生后 24—48 小时内部署卫星电话、卫星终端及其他应急通信设备；ITU 还持续推动国家应急电信计划（NETP），截至报告所引资料显示已开发 44 个国家版本。[3][4] 应急通信通常采用多层保障：卫星通信提供远距离回传，蜂窝网络在可用时承担常规通信，专用无线电和 Mesh 系统补充现场协同。

LoRa Alliance 于 2026 年 9 月公布，全球 LoRaWAN 设备部署量达到 1.5 亿，并报告约 25% 的复合年增长率。[5] 该数据说明低功耗广域无线技术生态和供应链具有一定规模，但 LoRaWAN 部署量不等于 LoRa-DTN 应急通信设备数量，不能直接作为项目 TAM。

## 4.3 市场规模：TAM / SAM / SOM

目前不建议直接引用全球应急通信、物联网、LoRaWAN 或数字孪生市场规模作为织网行动的 TAM。更稳妥的方式是围绕具体客户单位和部署需求自下而上测算。

| **指标** | **推荐定义** | **计算方式** | **需收集的数据** |
| --- | --- | --- | --- |
| TAM | 全球理论上存在断连关键消息通信需求且可部署此类系统的组织/单位。 | 目标单位总数 × 每单位平均部署套数 × 单套硬件/软件/服务价值。 | 各国消防/应急/林业/能源/矿业/机器人单位数量；典型部署规模；竞品及替代方案价格。 |
| SAM | 技术、法规、渠道和售后能力能够覆盖的可服务市场。 | 符合频段法规且场景适配的目标单位数 × 可服务部署比例 × 平均合同金额。 | 国家频谱与设备准入规则、目标区域、可达渠道、认证要求、部署条件。 |
| SOM | 团队未来3年现实可获取的市场。 | 三年可触达并转化客户数 × 平均合同金额（分硬件、软件和服务）。 | 团队销售资源、试点转化率、生产能力、渠道合作、交付周期和售后能力。 |

## 4.4 情景测算的必要输入

建议建立保守、基准、积极三种情景，逐项填写目标客户数量、每客户节点数、单节点成本、整套售价、软件/服务收入、试点转化率和年度交付能力。价格输入应至少通过 3 家供应商询价和 5—10 家潜在客户访谈获得；在数据缺失时应明确标注假设，不用电商最低展示价或未经核实的市场报告数字替代。

# 5. 细分市场与渠道

## 5.1 应用场景细分与进入优先级

| **场景** | **实际通信痛点** | **项目适配度** | **进入建议** |
| --- | --- | --- | --- |
| 自然灾害与应急救援 | 基站断电、光纤受损、道路阻断；现场队伍需要短消息、位置和告警。 | 中高（需实测覆盖、可靠性和抗环境能力） | 先做演示与非关键任务试点；通过验证和认证后再进入正式救援系统。 |
| 森林、山地及偏远巡检 | 蜂窝覆盖不连续；巡检人员分散，异常信息需要延迟回传。 | 高（短消息、低频状态上报） | 适合作为早期场景，与巡检服务商或野外作业团队合作。 |
| 矿山、隧道及地下空间 | 无线传播复杂，设备安全和可靠性要求高。 | 潜在需求高，当前准入门槛高 | 暂不作为首发商业市场；需专门传播测试、防爆及行业认证。 |
| 人道主义援助与临时营地 | 临时设施、通信资源不足，人员和物资状态需共享。 | 中（取决于节点部署与人员流动） | 可与NGO、应急通信集成商开展小规模验证。 |
| 移动机器人与无人系统 | 移动节点间歇接触，需要低速状态、任务和告警同步。 | 高（与项目计划中的移动节点方向一致） | 建议作为较早的技术验证和商业试点市场。 |
| 高校与科研实验室 | 需要可复现实验平台研究DTN、LoRa和移动网络。 | 很高（首年交付与该客户群匹配） | 优先形成教学科研套件和实验平台。 |

优先级判断：短期优先考虑高校/科研实验室、移动机器人研发团队、野外巡检团队和应急通信集成商；矿山、隧道和正式救援单位作为中长期市场，前提是完成可靠性、安全与合规验证。

## 5.2 客户细分

按组织类型可将潜在客户分为公共部门、公共安全机构、行业企业、系统集成商和科研/机器人机构。不同客户对采购成熟度、可靠性、接口、维护和认证的要求差异明显。

## 5.3 建议的市场进入渠道

- 科研合作渠道：通过高校实验室、科研项目和竞赛展示进入，以科研/演示套件、实验数据和技术文档建立早期使用案例。
- 行业合作渠道：与林业、能源、野外巡检服务商及移动机器人企业联合试点，围绕低频状态上报、异常告警和移动节点通信验证需求。
- 系统集成商渠道：与应急通信集成商、专网服务商合作，将节点和软件作为现有应急通信方案的补充模块；需要提供接口、部署、培训和售后支持。
- 公共采购渠道：待产品完成可靠性测试、设备认证和合规审查后，再参与政府/消防/公共安全采购；不宜作为研发初期唯一销售路径。

以上渠道为基于现有客户画像和商业化路径提出的进入建议，并非已经建立的合作关系或已验证的渠道订单。

# 6. 客户与需求

## 6.1 客户画像与采购关注点

| **客户类型** | **典型决策者/使用者** | **购买动机** | **采购关注点** |
| --- | --- | --- | --- |
| 政府应急管理部门 | 应急通信保障部门、装备采购部门、现场指挥人员 | 灾害期间保持最低限度的信息交换和现场态势感知。 | 可靠性、互操作、设备认证、部署速度、维护培训、供应商服务能力。 |
| 消防与公共安全机构 | 消防通信部门、采购部门、现场队伍 | 在复杂地形或通信中断时维持队伍协同。 | 抗冲击、防水、续航、易用性、网络安全和与现有系统兼容。 |
| 行业系统集成商 | 解决方案经理、技术负责人、项目采购 | 将产品纳入应急通信、专网或行业数字化整体方案。 | 接口开放、可集成性、稳定供货、技术支持、项目交付能力。 |
| 野外巡检/能源/林业企业 | 运维负责人、安全负责人、现场人员 | 偏远区域异常告警和状态回传。 | 覆盖实测、成本、续航、安装维护、与现有平台对接。 |
| 机器人与科研机构 | 实验室负责人、研发工程师、采购/资产部门 | 研究移动网络、延迟容忍通信和机器人状态同步。 | 开发文档、API、数据导出、实验可复现、成本。 |

## 6.2 采购逻辑与付费证据

公共部门采购往往不仅比较设备单价。澳大利亚 Fire and Rescue NSW 的无线 Mesh 采购评审中，非价格因素占 80%，包括技术、可靠性、兼容性、互操作、监控报告、支持和网络安全；价格占 20%。[7] 这说明产品化必须把可靠性证据、系统兼容性和售后能力作为重点。

公开采购记录显示，美国 DHS 曾采购 goTenna mesh radio equipment and services；澳大利亚 Fire and Rescue NSW 授予无线 Mesh 合同；中国地方应急部门存在卫星通信装备采购；挪威 DSB 发布通信设备框架协议采购公告。相关金额、采购性质和边界见附录 B。

这些案例证明政府和公共安全部门会为应急通信设备与服务付费，但大多属于成熟 Mesh 或卫星通信产品，不能直接证明客户会采购织网行动。项目仍需通过访谈、试点和报价测试验证自身付费意愿。

## 6.3 需求验证问题

1. 客户目前在通信中断或覆盖盲区中使用什么替代方案？
2. 短消息、位置、告警和设备状态信息的交换频率及延迟容忍度如何？
3. 是否存在移动节点、断续接触或无法持续建立端到端链路的情况？
4. 客户对交付率、时延、续航、覆盖、抗环境能力和网络安全的最低要求是什么？
5. 预算由哪个部门承担，采购周期、试点审批和设备准入流程如何？

# 7. 竞争格局

## 7.1 差异化定位建议

- 不要把“LoRa 低成本”作为唯一卖点，应在相同硬件和场景下证明断连保存、移动携带转发、缺片续传、消息最终交付和短窗口资源调度。
- 将数字孪生定位为可验证的研发与运维工具，而不是单纯三维可视化；核心证据包括实测日志回放、模型校准误差、留出场景验证和策略对照。
- 针对 goTenna 等竞品，采用公开规格对比、实机测试和用户访谈，不基于资料缺失推断竞品不具备某项能力。
- 避免与高性能 MANET 在宽带、语音、视频、抗干扰和成熟认证上正面竞争；突出低速、低成本、断连容忍和可解释调度。

# 8. 驱动因素、趋势与外部影响

## 8.1 需求驱动因素

- 灾害与关键基础设施中断：灾害可能导致基站断电、光纤受损、道路阻断，现场仍需要交换求助、位置和告警等短消息。
- 多层应急通信体系：卫星、蜂窝、专用无线电和 Mesh 形成互补，给局部断连环境下的补充型系统留下应用空间。
- 低功耗无线生态：LoRaWAN 设备生态和供应链发展，为低功耗无线节点的研发和供应提供基础，但不等于目标产品市场已经形成。
- 移动化与间歇连接场景：移动机器人、无人系统和偏远巡检存在节点移动、链路间歇接触等问题，与 DTN 的技术路线具有适配性。

## 8.2 外部影响与约束

- 技术约束：LoRa 带宽有限，实际覆盖、吞吐和丢包受天线、遮挡、功率、频段和环境影响。
- 法规约束：频段、发射功率、占空比、设备型号核准、进口和许可要求存在国别差异，不能将单一模块视为全球通用。
- 采购约束：公共采购重视可靠性、互操作、供应商履约、维护和服务能力，产品性能之外还需建立交付体系。
- 行业准入：矿山、隧道和正式救援场景对防爆、可靠性和责任要求较高，进入前需专项测试与认证。

## 8.3 行业发展趋势判断

从公开资料可观察到，应急通信更强调多层保障、系统互补和现场协同；采购评价也不仅关注设备价格，而是同时考察可靠性、兼容性、网络安全、部署和持续服务。对织网行动而言，数字孪生和 DTN 的价值需要通过实验日志、模型校准和可重复验证体现，而不能仅依靠概念性描述。

# 9. 机会、风险与情景

## 9.1 SWOT 分析

| **优势 Strengths** | **劣势 Weaknesses** |
| --- | --- |
| 聚焦断连和短接触窗口，应用问题明确；LoRa硬件路线具备低功耗和成本控制潜力；DTN缓存、续传和调度可形成系统级研究特色；数字孪生可支撑可视化解释和实验复现。 | 当前仍为研发规划阶段，缺少真实环境实测性能、认证和客户案例；LoRa带宽有限；模块接口对底层参数控制存在约束；团队尚未验证续航、抗干扰、复杂地形传播和规模化稳定性。 |

| **机会 Opportunities** | **威胁 Threats** |
| --- | --- |
| 灾害与基础设施中断带来应急通信需求；政府与公共安全部门已有相关设备采购；偏远巡检、机器人和科研场景可作为较低门槛切入点；可与卫星和蜂窝系统互补。 | goTenna、KANGLONG、Persistent、Rajant及卫星通信供应商已形成竞争；无线电频谱和设备认证具有国别差异；矿山/救援准入门槛高；客户高度重视可靠性、互操作和售后；成熟方案可能通过渠道和品牌形成壁垒。 |

## 9.2 关键风险与应对措施

| **风险** | **影响** | **建议措施/证据要求** |
| --- | --- | --- |
| 无线性能与覆盖不确定 | LoRa实际距离、吞吐和丢包受天线、遮挡、功率、频段和环境影响。 | 不使用厂商标称距离替代实测；建立不同场景下交付率、时延、吞吐和失败原因数据。 |
| 短接触窗口传输失败 | 接触时间不足以完成控制交换或消息分片传输。 | 测量接触时长分布；测试分片长度、ACK开销、续传和窗口感知调度；保留固定策略回退。 |
| DTN消息保存与交付语义 | 中继收到不代表目的节点收到；断电或缓存满可能丢失消息。 | 区分逐跳ACK和最终交付ACK；测试持久化、重启恢复、去重、TTL、缓存溢出和副本预算。 |
| 数字孪生模型失准 | 模型预测与真实链路偏差可能导致错误策略。 | 分离校准集和留出验证集；报告预测误差；收益不稳定时仅用于离线分析。 |
| 电池续航与设备可靠性 | 现场节点可能无法持续工作或遭受环境损坏。 | 测量实际功耗；设计外壳、防水防尘和抗冲击测试；建立电池与连续运行记录。 |
| 网络安全与隐私 | 求助、位置和任务信息可能被窃听、伪造或滥用。 | 设计身份认证、消息完整性、密钥管理、访问控制和数据最小化；避免未经验证宣称端到端安全。 |
| 频谱与设备准入 | 433MHz等频段规则、发射功率和设备认证在各国不同。 | 逐国核查频率、功率、占空比、设备型号核准、进口和许可要求；不可把单一模块视为全球通用。 |
| 高风险行业认证 | 矿山、隧道和正式救援场景对防爆、可靠性和责任要求高。 | 先避开高风险首发市场；取得专项认证并完成行业试点后再进入。 |
| 市场信任与售后 | 公共采购重视供应商履约、兼容、维护和服务能力。 | 通过集成商合作；建立测试报告、部署手册、备件、培训和响应机制。 |

# 10. 结论与行动建议

全球灾害风险、基础设施中断和政府应急通信采购共同证明，应急通信具有真实且持续的社会需求和付费市场。但这并不意味着任何新型无线通信方案都能自然获得采购。织网行动的商业机会应建立在明确的细分场景、可验证的性能、合规的无线电方案和可持续的交付服务之上。

建议团队将首年目标聚焦为“做出可信的技术证据”：证明系统在可重复的断连和移动条件下能够保存消息、利用接触机会完成续传、正确确认最终交付，并且数字孪生模型能够解释和改善实物表现；随后通过用户访谈和行业试点验证真实需求与付费意愿。

## 附录 C：数据使用与口径说明

- 灾害影响人口、基础设施损坏和经济损失属于行业需求背景，不是通信设备市场收入。
- LoRaWAN部署量是生态规模指标，不代表LoRa-DTN应急通信产品装机量。
- 政府采购数据必须区分已授予合同、成交公告、招标需求、框架协议预计金额和研发资助。
- 厂商公布的距离、续航和节点数量属于厂商声明；除非有独立测试，不应写成织网行动可达到的性能。
- 所有项目性能目标均应标注为“计划验收目标”；实测结果应注明设备、固件、天线、频段、功率、环境、样本量和测试方法。
- 本报告为团队内部市场调研底稿，不构成产品认证意见、法律意见或最终投资预测；正式对外使用前应复核各采购链接、金额和法规版本。

## 附录 E：术语与缩写

| **术语** | **说明** |
| --- | --- |
| **LoRa** | 一种低功耗远距离无线通信技术；具体可用频段、功率和合规要求因地区而异。 |
| **LoRaWAN** | 基于 LoRa PHY 的低功耗广域网络协议生态；其设备部署量不可直接等同于 LoRa-DTN 应急产品市场。 |
| **DTN** | 延迟/容忍网络，在链路断续时通过存储、携带和转发完成消息传递。 |
| **MANET** | 移动自组织网络，节点可动态组网并转发数据。 |
| **Mesh** | 网状网络，节点之间可通过多跳方式进行通信。 |
| **TAM / SAM / SOM** | 理论可寻址市场 / 可服务市场 / 可获取市场。 |
